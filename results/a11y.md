## Failures by library

A **Cause** line marks a failure that was reproduced by hand outside the harness, and says whether it comes from the library or from the scenario code (hand-written pieces or a deviation from the library docs). A failure without one has not been reviewed yet.

### forty-cdk

- **accordion** `accordion.aria-controls-collapsed` (optional): collapsed "Returns" header has no aria-controls · [APG](https://www.w3.org/WAI/ARIA/apg/patterns/accordion/#roles_states_properties)
  - **Cause: scenario.** the scenario unmounts closed panels with `@if`, one of the two ways the forty README documents (the other needs CSS); the README states that the trigger then emits `aria-controls` only while expanded.
- **tabs** `tabs.aria-controls-inactive` (optional): inactive tab "Security" has no aria-controls · [APG](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/#roles_states_properties)
  - **Cause: scenario.** the scenario unmounts inactive panels with `@if` (the forty README offers that or CSS); `aria-controls` is emitted only for a registered panel, so an unmounted one has none.

### ng-primitives

- **accordion** `accordion.panel-rendering` (required): panel text "Orders ship within two business days." is rendered on screen, expected not rendered · [APG](https://www.w3.org/WAI/ARIA/apg/patterns/accordion/#roles_states_properties)
  - **Cause: library.** ng-primitives sets `hidden="until-found"` on a closed panel only once its measured height is 0, which needs consumer CSS that collapses it; with none (SCENARIOS rule 4) a panel the user closes stays rendered and exposed with `data-exit` set. Initially closed panels are hidden. The CSS is not recorded in NOTES.md.
- **accordion** `accordion.enter-toggles` (required): panel text "Orders ship within two business days." is exposed in the accessibility tree, expected hidden · [APG](https://www.w3.org/WAI/ARIA/apg/patterns/accordion/#keyboard_interaction)
  - **Cause: library.** ng-primitives sets `hidden="until-found"` on a closed panel only once its measured height is 0, which needs consumer CSS that collapses it; with none (SCENARIOS rule 4) a panel the user closes stays rendered and exposed with `data-exit` set. Initially closed panels are hidden. The CSS is not recorded in NOTES.md.
- **accordion** `accordion.space-toggles` (required): panel text "Orders ship within two business days." is exposed in the accessibility tree, expected hidden · [APG](https://www.w3.org/WAI/ARIA/apg/patterns/accordion/#keyboard_interaction)
  - **Cause: library.** ng-primitives sets `hidden="until-found"` on a closed panel only once its measured height is 0, which needs consumer CSS that collapses it; with none (SCENARIOS rule 4) a panel the user closes stays rendered and exposed with `data-exit` set. Initially closed panels are hidden. The CSS is not recorded in NOTES.md.
- **menu** `menu.name` (required): the menu has aria-labelledby=null and aria-label=null · [APG](https://www.w3.org/WAI/ARIA/apg/patterns/menubar/#roles_states_properties)
  - **Cause: library.** the library puts no `aria-labelledby`/`aria-label` on the menu, and the scenario does not add one by hand.
- **menu** `menu.item-focus-model` (optional): items with tabindex >= 0: Edit (0) · [APG](https://www.w3.org/WAI/ARIA/apg/patterns/menubar/#roles_states_properties)
  - **Cause: library.** roving tabindex: the active item has `tabindex="0"`, as in the roving-tabindex practice the menu pattern links to; the menu text asks for `-1` on every item.
- **menu** `menu.arrow-down-opens` (optional): no visible role=menu element after opening · [APG](https://www.w3.org/WAI/ARIA/apg/patterns/menu-button/#keyboard_interaction)
  - **Cause: library.** arrow keys open the menu only when `arrowkey` is added to the trigger triggers; the default is `click` only.

- **menu** `menu.typeahead` (optional): expected focus on menu item "Duplicate", focus is on <button role=menuitem> "Edit" · [APG](https://www.w3.org/WAI/ARIA/apg/patterns/menubar/#keyboard_interaction)

  - **Cause: library.** the menu always installs a focus trap (by design, per a comment in its source), so Tab cycles inside the open menu instead of leaving and closing it.

## Not applicable

- `dialog/angular-aria`: No dialog entry point; the Angular team points to `@angular/cdk/dialog` (the Angular CDK column).
- `tabs/angular-cdk`: `@angular/cdk` has no tabs primitive.
- `menu/spartan`: brain has no menu primitive; Spartan's dropdown menu is a styled wrapper over `@angular/cdk/menu` (the Angular CDK column).
- `listbox/spartan`: brain has no standalone listbox; listbox roles exist only inside its combobox, select and command widgets.
- `combobox/angular-cdk`: `@angular/cdk` has no combobox; the experimental one ships separately in `@angular/cdk-experimental`.
