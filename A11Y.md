# Accessibility conformance: method

The accessibility benchmark checks every built scenario against the [WAI-ARIA Authoring Practices (APG)](https://www.w3.org/WAI/ARIA/apg/patterns/) pattern it claims to implement, in a real Chromium, and runs axe-core over the page. Results: [`results/a11y.md`](results/a11y.md) (summary) and [`results/a11y.json`](results/a11y.json) (raw).

## Running

```bash
node scripts/a11y.mjs                     # every built scenario
node scripts/a11y.mjs "menu/*" "*/forty"   # same <pattern>/<library> filters as the smoke probe
```

Scenarios must be built first (`pnpm bench:build`). The full run takes about two minutes: two scenarios at a time, each with its own static server, on one Chromium.

## What is checked

The checks live in [`a11y.config.mjs`](a11y.config.mjs), one list per pattern, each with an id, a level and a link to the APG section it comes from. They are written from the APG text, not from any library's behavior, and the scenario labels and data come from [SCENARIOS.md](SCENARIOS.md).

| Pattern   | APG source                                                                                                                                                                     | Required | Recommended | Optional |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------- | ----------- | -------- |
| Accordion | [Accordion](https://www.w3.org/WAI/ARIA/apg/patterns/accordion/)                                                                                                               | 7        | 0           | 2        |
| Tabs      | [Tabs](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)                                                                                                                         | 11       | 2           | 3        |
| Menu      | [Menu Button](https://www.w3.org/WAI/ARIA/apg/patterns/menu-button/), with keyboard inside the menu from [Menu and Menubar](https://www.w3.org/WAI/ARIA/apg/patterns/menubar/) | 11       | 0           | 9        |
| Listbox   | [Listbox](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/)                                                                                                                   | 7        | 2           | 1        |
| Combobox  | [Combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/), listbox popup, list autocomplete                                                                               | 14       | 0           | 2        |
| Dialog    | [Dialog (Modal)](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)                                                                                                       | 9        | 1           | 2        |

They cover three areas:

- **Roles, states and properties**: roles and ownership, accessible names (`aria-label` or `aria-labelledby`, computed by Playwright's accessible-name engine), `aria-expanded`, `aria-selected`, `aria-controls` that resolves to the right element, `aria-haspopup`, `aria-autocomplete`, `aria-modal`, `aria-labelledby` from tabpanel to tab.
- **Keyboard**: the APG keyboard table of each pattern, key by key (Enter, Space, arrows with the wrapping the APG specifies, Home/End, typeahead, Escape, Tab and Shift+Tab into, through and out of the widget, the dialog focus trap).
- **Focus management**: where focus lands when a popup opens, when it closes, and when the user tabs in.

### Levels

- **required**: the APG lists the role, state, property or key behavior as part of the pattern.
- **recommended**: the APG says "recommended", "should" or "strongly recommended" (e.g. automatic tab activation, typeahead in a listbox, a visible close button in a dialog).
- **optional**: the APG marks it "(Optional)" or "optionally", or the APG text is ambiguous (below).

### Checks made optional because the APG is ambiguous

| Check                                | Why it is optional                                                                                                                                                                                                                                                                                                     |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `accordion.aria-controls-collapsed`  | The APG requires `aria-controls` on every header but never says whether a collapsed panel stays in the DOM; unmounting it leaves the reference dangling or forces dropping it. The combobox pattern relaxes `aria-controls` to "only while visible"; the accordion pattern is silent. The expanded header is required. |
| `tabs.aria-controls-inactive`        | Same question for inactive tab panels. The active tab is required.                                                                                                                                                                                                                                                     |
| `tabs.vertical-arrows-ignored`       | "A horizontal tab list does not listen for Down Arrow or Up Arrow" appears in a note, not in the keyboard table.                                                                                                                                                                                                       |
| `menu.item-focus-model`              | The menu pattern says every item has `tabindex="-1"` (or the container uses `aria-activedescendant`), but the practice it links to defines roving tabindex with `tabindex="0"` on the active item. Tab closes the menu either way.                                                                                     |
| `menu.focus-return-after-activation` | The keyboard table says Enter "activates the item and closes the menu" but does not say where focus goes (it does for Escape). SCENARIOS.md requires the return, so a failure is still worth reading.                                                                                                                  |
| `combobox.selected-follows-active`   | The APG ties `aria-selected="true"` to the value "visually indicated as the currently selected value". Unstyled scenarios indicate nothing, and implementations differ on separating highlight from selection.                                                                                                         |
| `dialog.focus-return-delete`         | The APG allows focus to go elsewhere when the workflow makes it more logical (e.g. after an irreversible action). Escape and Cancel are required.                                                                                                                                                                      |

### Interpretations worth knowing

- `menu.home-end-or-wrap` (required) encodes the APG's condition: Home and End are required only "if arrow key wrapping is not supported". `menu.arrow-wrap` and `menu.home-end` report each on its own as optional.
- `listbox.keyboard-selection` (required): the single-select listbox table does not name a selection key, but a listbox whose selection cannot be changed from the keyboard is not operable. Selection following focus, Space or Enter all pass.
- `accordion.panel-rendering` and `tabs.panel-rendering` (required) check what is drawn on screen; the other panel checks check the accessibility tree. They are separate so a library that hides content from assistive technology but leaves visual hiding to consumer CSS shows exactly that. SCENARIOS.md forbids styling, so a failure here usually means the scenario lacks CSS the library needs.
- `combobox.autocomplete` reads `aria-autocomplete` both collapsed and open: the APG ties it to the autocomplete behavior, which does not change when the popup closes, and screen readers announce it on focus.

### APG alternatives accepted

- **Effective focus**: DOM focus, or the element referenced by the focused element's `aria-activedescendant`. Focus assertions compare against that, so roving tabindex and active-descendant implementations are judged the same way. The combobox is the exception: the APG requires DOM focus to stay on the input there.
- `aria-selected` or `aria-checked` for listbox options (not both); selection following focus or explicit selection.
- A combobox that highlights the first match automatically: Down Arrow is then expected on the following option, as the APG specifies.
- `aria-modal="true"`, a native `<dialog>` shown modally, or content outside the dialog under `aria-hidden="true"` or `inert`.
- Initial dialog focus on any element inside the dialog, including the dialog container.
- Collapsed combobox `aria-expanded` unset (its default is `false`); `aria-haspopup` unset (implicit `listbox`) or `listbox`; trigger `aria-haspopup` `menu` or `true`.
- Menu items with role `menuitem`, `menuitemcheckbox` or `menuitemradio`; a menu named by `aria-labelledby` pointing at the button or by `aria-label`.

## How a check runs

- Every check gets a fresh browser context and page, so checks are independent; a check that needs a "before" and "after" Tab stop injects two plain buttons at the start and end of `<body>`.
- Keys go through Playwright's keyboard (trusted events). Assertions poll for up to 1.5 s, so asynchronous rendering and focus moves are not mistaken for failures; negative assertions (e.g. "Down Arrow does nothing") wait for two animation frames and 250 ms first.
- A failing check is retried once on a new page. If it passes the second time it is recorded as a pass marked flaky († in the report), with the first failure message kept.
- "Rendered" means `checkVisibility()` and a layout box; "exposed" additionally means not inside `aria-hidden="true"` or `inert`.
- Failures are reproduced by hand outside the harness before a report is published. The `notes` map in `a11y.config.mjs` records the cause, library or scenario code (hand-written parts, missing CSS, or a deviation from the library docs), and the report prints it under the failure; a failure without a note has not been reviewed yet.

## axe-core

axe-core runs on the whole document with `runOnly` tags `wcag2a, wcag2aa, wcag21a, wcag21aa, wcag22aa`, in the initial state of every scenario and in the open state of the popup patterns (menu open after a click, combobox open after typing "an", dialog open). Violations are recorded per state with rule, impact, node count and the first target. Rules that depend on layout or color (`target-size`, `color-contrast`) say little about unstyled scenarios; the report notes when a hit comes from missing consumer CSS.

## Not covered

- **Real screen readers.** The checks verify the ARIA contract that screen readers consume, not what they announce. Use the manual protocol below.
- Pointer and touch behavior beyond the clicks used to set up a state, outside-click dismissal, and whether a modal blocks pointer input to the page behind it (in unstyled scenarios the backdrop is consumer CSS).
- RTL, vertical orientations, `prefers-reduced-motion`, forced colors, zoom/reflow and color contrast.
- Disabled items, nested menus, multi-select listboxes and other variants the scenarios do not include.
- Browsers other than Chromium.

## Manual screen reader protocol

Run each scenario with NVDA (latest) on Chrome and on Firefox, and with VoiceOver on Safari (latest macOS). Serve a build with any static server, e.g. `python -m http.server 4300 -d dist/scenarios/tabs--forty/browser`. Exact wording varies by screen reader; what matters is that the role, name and state are announced and stay in sync.

### Accordion

- [ ] Tabbing to "Shipping" announces a button, its name, "expanded" and heading level 3.
- [ ] "Returns" announces "collapsed"; Enter announces "expanded", and moving back to "Shipping" announces "collapsed".
- [ ] In browse mode (NVDA) / with the VO cursor, the three headings are listed in the headings list, and collapsed panel text cannot be read.
- [ ] If the panels are regions, the landmark list shows them named after their header.

### Tabs

- [ ] Tabbing in announces the tab list name "Account settings", "Profile", tab, selected, 1 of 3.
- [ ] Right Arrow announces "Security", selected, 2 of 3; NVDA stays in focus mode.
- [ ] Tab from the tab list lands on the panel (or its first control) and announces it as a tab panel named "Security".
- [ ] In browse mode / with the VO cursor, only the active panel's text can be read.

### Menu button

- [ ] The trigger announces "Actions", menu button (VO: pop-up button), collapsed.
- [ ] Enter announces the menu (with its name, if any) and "Edit", menu item, 1 of 3.
- [ ] Down/Up Arrow announce each item; Escape returns to "Actions" and announces "collapsed".
- [ ] Activating "Duplicate" returns to the trigger without announcing stray content.

### Listbox

- [ ] Tabbing in announces "Fruits", list box, "Apple", not selected, 1 of 5 (NVDA switches to focus mode).
- [ ] Arrow keys announce each option with its selection state; selecting announces "selected".
- [ ] Tabbing out and back in returns to the selected option.

### Combobox

- [ ] Focusing the input announces "Fruit", combo box, collapsed, editable, and that it has autocomplete.
- [ ] Typing "an" announces the expanded state (and a result count if the implementation provides one).
- [ ] Down Arrow announces "Banana" (or "Mango" if Banana was highlighted automatically) with its position, while the caret stays in the input; check VoiceOver + Safari particularly, as `aria-activedescendant` support there is the weakest.
- [ ] Enter puts the label in the input, announces it and "collapsed"; Escape closes the popup and announces "collapsed".

### Dialog (modal)

- [ ] Enter on "Open dialog" announces "Delete file?", dialog, the description "This action cannot be undone." and the focused button.
- [ ] Tab and Shift+Tab cycle between Cancel and Delete only.
- [ ] In browse mode / with the VO cursor, content outside the dialog cannot be reached.
- [ ] Escape closes the dialog and announces "Open dialog", button.
